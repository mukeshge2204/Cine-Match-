ABSTRACT

CineMatch AI is a content-based movie recommendation system that suggests relevant
movies to a user based on the content similarity of movies. The system leverages machine
learning techniques, particularly vectorization and cosine similarity, to identify movies
that share thematic and descriptive features with a movie selected by the user. The
application is built using Python and delivered via a Streamlit web interface, providing
an interactive, Netflix-style user experience. The system integrates real-time metadata
(cover art, release year, and IMDb rating) using the OMDb API. This report presents the
complete software development lifecycle for CineMatch AI, including requirement
analysis, system design, algorithm selection, implementation details, testing, and results.
The report also provides a discussion on limitations and future enhancements to improve
personalization, scalability, and user experience.

CHAPTER 1
INTRODUCTION

1.1 Background and Context

In the era of digital entertainment, users are exposed to an overwhelming volume of
content across multiple streaming platforms. Users often struggle to decide what to
watch because of the vast number of available titles and the limited time for decision
making. Recommendation systems solve this information overload problem by providing
personalized suggestions based on user preferences, viewing behavior, or content
characteristics. Such systems are widely used by Netflix, Amazon Prime, Disney+, and
many other platforms to improve user engagement and retention.

Recommendation systems are commonly classified into collaborative filtering, content-
based filtering, and hybrid approaches. Collaborative filtering relies on collective user
behavior such as ratings and viewing history to infer preferences, whereas content-based
filtering uses attributes of items (e.g., genre, cast, keywords, descriptions) to compute
similarity. Hybrid approaches combine both to mitigate the limitations of individual
methods. For a new system with limited user history, a content-based approach is a
practical and efficient choice.

CineMatch AI focuses on content-based recommendations. The system uses movie
metadata and textual features to compute similarity between titles. A user selects a
movie, and the system returns a list of similar movies. The project is implemented using
Python and machine learning libraries, with an interactive Streamlit interface to deliver
a visually appealing user experience.

Figure 1.1: System overview of CineMatch AI (placeholder). The diagram depicts the
flow from user selection to recommendation generation, and the integration with OMDb
for metadata retrieval.

1.2 Motivation

The motivation for CineMatch AI stems from the need to help users quickly find relevant
movies without extensive browsing. In many streaming services, recommendations are
considered a core feature, yet smaller platforms or local deployments may lack
sophisticated systems due to high cost or limited data. A lightweight content-based
recommender can be deployed with minimal user data and still provide meaningful
suggestions. Additionally, the combination of a recommendation algorithm with a
user-friendly UI makes the system accessible for students, small businesses, and
educational demonstrations.

By building CineMatch AI, the project demonstrates practical machine learning concepts
such as feature extraction, vectorization, similarity computation, and caching. It also
showcases integration of external APIs for enhanced metadata, which is a common
industry requirement. The project therefore bridges theoretical knowledge with real-
world application development.

1.3 Problem Statement

The problem addressed in this project is: "How can we build a lightweight, accurate,
content-based movie recommendation system that provides real-time metadata and an
intuitive user experience without relying on extensive user profiles or rating data?"

1.4 Objectives

The objectives of the project are:
• To create a content-based movie recommendation system.
• To generate top-N recommendations using cosine similarity.
• To integrate real-time metadata such as posters and ratings using OMDb API.
• To build an interactive web interface using Streamlit.
• To optimize performance using caching and efficient data loading.
• To document the entire development lifecycle, testing, and evaluation.

1.5 Scope and Limitations

Scope:
• The system recommends movies based on the similarity of content features.
• The system supports a predefined movie dataset and precomputed similarity matrix.
• Users can select any movie in the dataset and obtain a list of recommendations.
• The interface is accessible via a browser and can be deployed locally or on a server.

Limitations:
• The system does not personalize recommendations based on individual user history.
• Recommendation quality depends on the completeness and accuracy of metadata.
• The OMDb API may impose rate limits or require API key management.
• Cold-start issues for movies with minimal metadata may reduce quality.

3.1 System Architecture

The system architecture follows a lightweight three-tier design: data layer, logic layer,
and presentation layer. The data layer consists of preprocessed datasets and pickled
objects that store movie metadata and similarity matrices. The logic layer computes
recommendations and manages API communication. The presentation layer is implemented
with Streamlit, providing UI components for selection and display.

from user input to recommendation logic, and onward to UI rendering.

Figure 3.2: Recommendation pipeline (placeholder). Steps include data loading,

3.2 Module Design

Table 3.1: Module responsibilities
+---------------------------+-----------------------------------------------------+
| Module                    | Responsibility                                      |
+---------------------------+-----------------------------------------------------+
| Data Loader               | Load movie_dict.pkl and similarity.pkl              |
| Recommendation Engine     | Compute top-N similar movies                         |
| Metadata Service          | Fetch poster, year, and rating from OMDb            |
| UI Layer                  | Render selection, buttons, and results              |
| Cache Manager             | Cache API calls and loaded resources                |
+---------------------------+-----------------------------------------------------+

The modular design ensures separation of concerns. While the implementation is a
single-file Streamlit app, the logical separation makes the system easier to maintain
and extend. Each module is described below.

• Data Loader: Reads pickled movie data and similarity matrix. It validates file
  availability and provides error messages if missing.
• Recommendation Engine: Uses cosine similarity values to rank movies. It excludes the
  selected movie from recommendations and returns the top 10 items.
• Metadata Service: Calls the OMDb API to retrieve poster URLs, rating, year, and genre.
  It includes error handling and fallback placeholders.
• UI Layer: Displays the title, metadata cards, and organizes the two-row layout.
• Cache Manager: Streamlit caching decorators reduce repeated computation and API calls.

3.3 Algorithm and Blueprints

The recommendation algorithm is based on cosine similarity between feature vectors. The
feature vectors are constructed from textual metadata (such as genres, keywords, cast,
and overview). After preprocessing and vectorization, each movie is represented as a
vector in a high-dimensional space. The similarity between two movies is computed as:

sim(u, v) = (u · v) / (|u| * |v|)

Where u and v are vectors representing two movies. The algorithm sorts all movies by
similarity score with respect to the selected movie and returns the top 10 results.

Pseudocode:
1. Input: selected_movie
2. Locate index i of selected_movie in movie list
3. Compute similarity scores from precomputed matrix
4. Sort scores in descending order
5. Return top 10 movies (excluding selected_movie)
6. Fetch metadata for each recommendation and render output

3.4 Data Pre-processing and Feature Engineering

Data preprocessing is performed outside the Streamlit application and stored in
pickled form. Typical steps include:
• Merging multiple datasets containing movies, credits, and keywords.
• Cleaning missing values and removing duplicates.
• Combining text features (genres, keywords, cast, crew, overview) into a single
  "tags" field for vectorization.
• Applying normalization such as lowercasing, stemming, and removal of stopwords.
• Vectorizing text using CountVectorizer or TF-IDF.
• Computing cosine similarity matrix from the vectors.

These steps ensure that movies with similar thematic content have high similarity
scores. The preprocessing pipeline is essential for improving recommendation quality.

3.6 Security and Privacy Considerations

Although CineMatch AI does not store user personal data, it handles API keys for OMDb.
The API key should be secured through environment variables or configuration files and
should not be exposed in public repositories. Network communication should use HTTPS
where possible. The system avoids logging sensitive data and provides minimal exposure
by only fetching public metadata.

3.7 Deployment and Runtime Design

The system can be deployed locally using Streamlit or hosted on platforms such as
Streamlit Community Cloud or Heroku. The deployment steps include:
1. Install dependencies from requirements.txt.
2. Place precomputed models in the models directory.
3. Set OMDb API key configuration.
4. Run the command: streamlit run app.py.

At runtime, the system loads data once, caches it, and serves user requests quickly.

3.8 Complexity Analysis

Let n be the number of movies. The similarity matrix is an n x n matrix. Query time for
recommendations is O(n log n) due to sorting, or O(n) if a partial top-K method is used.
Memory complexity is O(n^2) for storing similarity. For small-to-medium datasets, this
is acceptable. For large-scale datasets, approximate nearest neighbor methods or sparse
similarity representations would be needed.
